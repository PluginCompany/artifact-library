A small field guide
for useful artifacts.

You’re one directory deeper now. The links and assets still resolve, using ../ to reach the report root.

What to include

  • A clear index.html entry point.
  • Local scripts, styles, images, fonts, and media.
  • Relative links between pages.
  • Source data so the report can be inspected.

What to leave behind

  • Symlinks; copy the actual asset instead.
  • Unrelated source directories and dependencies.
  • Absolute filesystem paths in page links.
  • Server-side code expecting an application runtime.

Common questions

Can the pages run JavaScript?

Yes. Browser JavaScript is served as an ordinary asset. The report’s chart fetches a local JSON file and updates without a framework or build step.

Does an update remove the old version?

No. Versions are immutable and retained indefinitely. The stable link moves forward; explicit version links remain fixed.

Can I download the artifact again?
artifact download rich-demo \
  --out ./downloaded-demo --json

The archive contains original files, without the update-notification script inserted into served HTML.

What if two agents update the same report?

Updates use expected revisions. A stale update returns a conflict so the agent can inspect and reconcile the newer snapshot first.

What if the upload response is lost?

The CLI saves the upload locally. Use the operation key shown in the error with artifact retry <operation-key> to recover the original result.
