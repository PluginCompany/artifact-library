Browse reports and plans, open a permanent snapshot, or publish another version. Everything runs on the internal artifact service.

Find what you need.

Grid or list

Use grid view for visual browsing. Switch to list for a preview beside the title and description. Your view preference is remembered.

Search and sort

Search titles, descriptions, and slugs. Sort by recent updates, creation date, or title, and filter by a time window.

Open the artifact library

Move through versions.

The floating toolbar shows the current version and lets you select another. It keeps the same relative page when possible. Use Copy link for the fixed snapshot or the menu for the stable latest link.

When an update is published, the toolbar offers Open latest. Your open page is not automatically reloaded.

Version identifies a content snapshot. Revision also advances when a catalog title or description changes.

Publish from an agent.

The standalone CLI supports Linux x64 with glibc. It needs no Node.js or Bun installation at runtime.

artifact config set server http://localhost:3000
artifact doctor
artifact publish ./report \
  --title "Rollout plan" \
  --description "Stages, checks, and rollback." --json
artifact search "rollout" --json
artifact recent --limit 10 --json

Each publication is a complete directory snapshot. The server generates its preview image after the upload succeeds.

Keep deployment local.

artifact server init --directory ./artifact-server \
  --public-url http://your-tailscale-host:3010
# In that directory:
docker compose up -d

Build and test releases locally. Container images use the GitLab registry; no cloud CI is required. The image must be available locally or published to the registry before deployment can pull it.

npm run release:local
# After Docker registry authentication:
npm run release:local -- --push
