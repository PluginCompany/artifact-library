How the artifact service works

A CLI packs a folder of HTML into a tarball. One Node.js process stores it as an immutable, numbered snapshot on a plain-file volume and serves it back at a stable link. A toolbar is added on the way out, a headless Chromium takes the preview picture, and readers' answers and comments are saved beside the artifact for the agent to read.

Design choices
  • Files, not a database. Every write is an atomic JSON rename with fsync; a journal replays interrupted commits.
  • Snapshots never change. The toolbar is injected while streaming, so stored bytes stay byte-identical.
  • Safe to retry. Uploads are saved before sending and keyed for idempotency.
  • Open by default, lockable. Reading is open; an optional write token protects publishing, archive and purge.
  • Feedback outside versions. What readers save never changes a snapshot.

Version vs revision

Easy to mix up

A version is a content snapshot. A revision is a concurrency token that also moves when only metadata changes. Send the revision when you update, and keep the version for links.

        Deployment

        One container, one named volume. Run exactly one server process per data volume, on a filesystem with atomic rename and fsync.

        1. Generate the config

          artifact server init --port 3010 checks Docker, finds a free port, detects the Tailscale IP, and writes compose.yaml and .env. It never overwrites an existing deployment.

        2. Start it

          docker compose up -d. Health is checked via /healthz every 30 s, with shm_size: 256mb for Chromium.

        3. Point the CLI at it

          artifact config set server <PUBLIC_BASE_URL>, artifact config set token <token> if the server has one, then artifact doctor.

        4. Upgrade

          Set ARTIFACT_IMAGE in .env, then docker compose pull && docker compose up -d. The volume is kept.

        # compose.yaml (excerpt)
services:
  artifacts:
    image: ${ARTIFACT_IMAGE:-ghcr.io/plugincompany/artifact-library:0.4.0}
    ports: ["${BIND_ADDRESS:-127.0.0.1}:${PORT:-3000}:3000"]
    environment:
      DATA_DIR: /data
      PUBLIC_BASE_URL: ${PUBLIC_BASE_URL:-http://localhost:3000}
    env_file: [{ path: .env, required: false }]  # ARTIFACT_TOKEN, MAX_*, PREVIEWS
    shm_size: 256mb
    volumes: [artifact-data:/data]
        Two imagesMulti-stage builds on node:22-bookworm-slim. The full target installs Playwright Chromium into /opt/playwright for previews; slim has no browser and previews off. Both build the seed and run as the node user. See Dockerfile.
