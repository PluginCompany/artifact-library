# Artifact reference collection

Polished example artifacts that show what a good artifact looks like for each common
job. Copy one as a starting point, swap the content, publish. A new server seeds all of
them on first start.

| Slug | Phase | What it demonstrates |
|---|---|---|
| `agent-guide` | Explain | How agents should plan, build, verify, publish and follow up on artifacts |
| `reference-collection` | Hub | Live catalogue of this collection and the kit style guide (`kit.html`) |
| `ref-plan-deck` | Plan | Keyboard slide deck, overview grid, speaker notes, print-to-PDF |
| `ref-decision-questionnaire` | Plan | Several decisions at once; answers saved for the agent |
| `ref-prototype-variants` | Plan | Clickable UI variants with picks and comments per variant |
| `ref-scope-slicer` | Plan | Work items against capacity, live timeline, saved proposals |
| `ref-decision-record` | Plan | Options, adjustable weighted scoring, readers record their position |
| `ref-live-run-log` | Build | Page driven by `artifact data set`; blockers answered on the page |
| `ref-debug-notebook` | Build | Bug investigation: hypotheses with evidence, root cause, fix |
| `ref-runbook` | Build | Operational procedure with shared ticks and rollback |
| `ref-implementation-review` | Review | Screenshot evidence for finished work: criteria, annotated shots, findings, verdict |
| `ref-code-walkthrough` | Review | A diff read by purpose, with verdicts and threads per chapter |
| `ref-visual-regression` | Review | Before/after/diff per screen, approve or request changes |
| `ref-test-report` | Review | Tests and performance against budgets, regenerated by a script |
| `ref-ops-report` | Report | Five pages, KPI tiles, charts with table views, one data file (sample bike workshop) |
| `ref-weekly-digest` | Report | Shipped / in progress / blocked for a week, built from git and the library |
| `ref-architecture-tour` | Explain | Clickable system diagram, step-through request flows, reference tables |
| `ref-codebase-map` | Explain | Treemap by size and churn, module graph, regenerated from git |
| `artifact-cli` | Explain | CLI install page, built from `scripts/release-page.html` |

## Layout

```
examples/reference/
  kit/                 shared design system: kit.css, kit.js, fonts/ (self-hosted, OFL)
  _template/           minimal starting page wired to the kit
  publish.sh           stage an artifact dir + kit, then publish or update
  <slug>/
    artifact.json      slug, title, description (catalogue metadata)
    index.html         entry page; an EDITING GUIDE comment at the top says what to change
    data.js / *.html   content that changes often lives in data, not markup
```

`kit/` is copied into every artifact at publish time (the server does not follow symlinks),
so each published artifact is self-contained and works without internet access.

## Saving answers, comments and verdicts

Load `kit/kit-data.js` after `kit/kit.js`. On the artifact server, pages save small JSON
documents beside the artifact (outside its versions); opened from disk they fall back to
browser storage and say so in `[data-save-status]`.

| Key | Shape | Written by |
|---|---|---|
| `comments.<anchor>` | `{ items: [{ id, author, role, createdAt, text, resolved }] }` | `Kit.comments(el, {key})`, `artifact data append` |
| `answer.<question>` | `{ choice, note }` | pages (questionnaires, picks) |
| `review.<item>` | `{ verdict: "approved" \| "changes" \| "question", note }` | review pages |
| `state.<name>` | anything | pages or agents (`artifact data set`) for live state |

Agents read everything with `artifact feedback <slug>` and reply in a thread with
`artifact data append <slug> comments.<anchor> --item '{"text":"…"}' --author "Claude Code"`.

## Publish

```bash
./publish.sh ref-ops-report "Added October numbers"
```

New slugs are published, existing ones updated. This folder is the source of truth:
an update replaces the live content.

## Conventions

- **Tokens, not hex.** Colours come from `kit.css` tokens (`--accent`, `--thread`, `--good`…).
  Dark mode is a separate set of tokens, toggled with `[data-theme-toggle]`.
- **Signature motifs:** mono uppercase eyebrows, Bricolage display headings, stitched
  (dashed `--thread`) section lead-ins, cards that lift on hover.
- **Status always has a word.** `tag good|warn|bad` carries a label; never colour alone.
- **Charts:** `Kit.chart.line|column|bar|donut|spark`. Series colours are fixed slots
  `--s1…--s5`; every chart card offers a table view. Never dual axes.
- **Responsive and printable:** no horizontal scroll at 375 px; print hides chrome.
- **Example content is labelled** as such on the page.
- Artifact-specific CSS/JS stays in the artifact; promote it to `kit/` only when two
  artifacts need it.
